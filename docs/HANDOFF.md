## 3. What the product does today

Free:

## 6. Lessons learned on this laptop (avoid repeating)

- **PowerShell 5.1 encoding:** `Get-Content`/`Set-Content` default to ANSI and garbled UTF-8 once. Use `[IO.File]::ReadAllText(p,[Text.Encoding]::UTF8)` / `WriteAllText(p,s,(New-Object Text.UTF8Encoding($false)))`, or the Desktop Commander `edit_block` tool (safest for code).
- In double-quoted PowerShell strings, `$x` and `${a.name}` interpolate (this blanked JS template literals once). Use single-quoted here-strings `@' ... '@` or `edit_block` for code containing `$`.
- PowerShell single-pair arrays must be `@(,@('a','b'))`; `@(@('a','b'))` flattens and once replaced every `.` with `f` in a file (restored from git). Always check replacements actually matched (print MISSING) and compile.
- `write_file` needs `mode: rewrite` for existing files. rustfmt rewraps lines, so text replacements against formatted code can silently miss.
- Tauri sync commands run on the main thread: every command touching the tree, file system, keyring or OS must be async.
- Windows hides cloud placeholders from apps by default; `cloud.rs` exposes them per thread only during checks.
- Windows 11 folder picker, Save dialog and Inno Setup dialogs are **not automatable** — automating the picker once scanned the owner's Downloads. Test by launching the app with a folder argument (`tessera-desktop.exe "C:\path"`, or `TESSERA_DEV_SCAN` in dev).
- Find windows **by process id, never by title** (a title search once read text from the owner's KeyStow and Notepad windows).
- The debug `target` folder grew to 30.7 GB and filled the disk; dev profile now uses minimal debug info. Check free space before big builds; `cargo clean` is safe.
- `npm install` with `NODE_ENV=production` pruned devDependencies; use `NODE_ENV=development` and `npm install --include=dev`.
- `Select-String` is case-insensitive by default (use `-CaseSensitive` for "FAILED").
- PowerShell `Invoke-WebRequest` can't follow 308 redirects; Cloudflare Pages adds trailing slashes.
- A debug build run without `npx tauri dev` shows a blank window (needs the Vite dev server).
- Disposable fixtures go in `.fixtures\<name>` with a `.tessera-fixture` marker and are deleted afterwards. Website screenshots come from a made-up `C:\Demo` folder so no personal paths appear.
- **GitHub Actions minutes are limited** (private repo; macOS minutes count 10x). Each push starts CI; pushing every few minutes used up the month on 27 Nov. Batch pushes, and docs-only pushes no longer trigger CI. `tools/check.ps1` runs the same checks locally.
- Windows PowerShell 5.1 with `$ErrorActionPreference = 'Stop'` stops the script when a native program's stderr is redirected (`*>`, `2>&1`): run such commands through `cmd /c "... > log 2>&1"`.
- `SetWindowPos` called from (non-DPI-aware) PowerShell takes logical coordinates: on this 125% screen, 800 x 480 gives a true 800 x 480-point window.
- Desktop Commander's `start_process` sometimes returns only the first lines of output; call `read_process_output` for the rest. Long jobs (> 4 min) must run with `Start-Process` in the background and be polled, or the tool call times out.
- The dev app and the installed app share all state (same identifier `app.tessera.desktop`): WebView settings such as "welcomed", the background-mode file in `%APPDATA%\app.tessera.desktop`, and the log in `%LOCALAPPDATA%\app.tessera.desktop\logs`. Leave settings as you found them after testing.
- macOS cross-checks from Windows: `cargo clippy --target aarch64-apple-darwin` works for scan, insights, cli and treemap; crates with C code (ring, blake3, objc2-exception-helper) need Apple's toolchain, so the desktop app itself can only be checked on GitHub's macOS runner.
- The Restore list contains the owner's own entries (they cleaned Hugging Face models, crash dumps and a temp file on 26 Nov ~22:04 and emptied the bin). Do not clear it.
- **27 Nov evening incident:** a PowerShell clean-up of the Restore list wiped it (25 owner entries) because Windows PowerShell 5.1's `ConvertFrom-Json` returns a JSON list as one object, so the filter saw one item. Restored byte-for-byte from the backup taken before testing. Now: back up `%LOCALAPPDATA%\app.tessera.desktop\recently-moved.json` before any test that cleans up, and only use `tools\bin-purge-fixture.ps1` (Node JSON edit, refuses anything outside `.fixtures`, keeps a backup in `target\`). Never edit owner JSON with PowerShell 5.1.
- **New Tauri commands must be added in three places**: `generate_handler!` in lib.rs, `COMMANDS` in `src-tauri/build.rs`, and `allow-...` in `capabilities/default.json`. Missing one shows "... not allowed. Command not found" only when the button is pressed; `src-tauri/tests/commands_allowed.rs` now fails the tests instead.
- `npx tauri dev` rebuilds and **restarts the app** when any workspace crate changes (not only src-tauri), losing the screen's state; edit Rust before a walkthrough, not during it. Interface edits reload in place.
- This laptop's shell has `NODE_ENV=production`: React's test helpers then fail ("React.act is not a function"). Set `$env:NODE_ENV='development'` before `npm test` (check.ps1 does). `tsc -b` (npm run build) is stricter than `tsc --noEmit -p .` (index checks): run the build before pushing interface changes.
- Driving the dev window: `tools/cdp-run.mjs` (click by text, type, select, wait, screenshot) over WebView2 DevTools; screenshots can then be read as images. The sidebar's Cleanup button text includes its count ("Cleanup32"): match with `clickre:^Cleanup\s*\d+$`.
- Test files held open: a hidden PowerShell child (`[IO.File]::Open(path,'Open','Read','None')` in a loop until a flag file is deleted) behaves like Word or a browser; Restart Manager names it "Windows PowerShell 5.1".
- **Release builds must use `NODE_ENV=production`.** check.ps1 and release.ps1 set `development` for the test tools, and Vite honours it during `tauri build`, so local installers from 27 Nov ~03:50 to ~20:30 IST shipped React's development version (575 KB bundle with `jsxDEV`; slower; every effect runs twice, which exposed a cleanup race). release.ps1 now builds with production and runs `tools\check-production-bundle.ps1`; check.ps1 too. For a manual `npx tauri build`, set `$env:NODE_ENV='production'` first.
- Tauri locks `window.__TAURI_INTERNALS__.invoke` (cannot be wrapped). To see what the screen asks the backend, use `tools/cdp-run.mjs` `net:on` / `net:FILE` (Network events for the ipc protocol). A release build can be driven the same way: start its exe with `WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS=--remote-debugging-port=9333 --remote-allow-origins=*` (page `http://tauri.localhost/`); remove the variable afterwards. Installed or packaged builds without the variable can be driven with `tools/ui-invoke.ps1` / `ui-type.ps1` / `capture-window.ps1` (UI Automation by process).
- Developer Mode is **on** on the owner laptop (owner allowed it, 27 Nov) for testing the Store package; `Get-AppxPackage BeyondEnterprises.Tessera*` shows whether a test install is present (remove it with `Remove-AppxPackage` when done).
- **28 Nov lessons:** Windows PowerShell 5.1 strips the double quotes from arguments given to native programs, so JSON passed to `node -e ... $json` arrives broken (publish-download.ps1 now passes it in an environment variable). Any `cargo` build, test or clippy run started directly from a tool call can exceed the 4-minute limit and dropped the whole laptop connection once: always start long jobs with `Start-Process -WindowStyle Hidden cmd /c "... > target\x.log 2>&1 & echo EXIT %ERRORLEVEL% >> target\x.log"` and poll the log. A `git push` carrying the installers (11 MB DMG) disconnected once ("unexpected disconnect while reading sideband packet"); retrying in the background worked. `formatBytes` uses 1024-based units, so screen tests must use 2**30 for "1.00 GB". The timing test `cancellation_mid_scan_leaves_consistent_partial_tree` (cancel < 1 s) can fail when the laptop is busy with several builds; rerun alone before suspecting the scanner. The MSIX can be checked quickly: `Add-AppxPackage -Register target\msix\layout\AppxManifest.xml`, open `shell:AppsFolder\<PFN>!Tessera`, look at the window by process id, then `Remove-AppxPackage`.
- The taskbar's pinned Tessera had been pointing at `target\debug\tessera-desktop.exe` (it opened "localhost refused to connect"); it now points at the installed copy. Dev and installed builds share the app identity, so pinning while a dev build runs can pin the dev exe.
